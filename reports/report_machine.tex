\section{Problem and dataset}
% ===========================================================================

We are given a classification problem: classify a machine into one of
three states using sensor measurements, with 0 for normal, 1 for thermal
failure and 2 for mechanical failure. Thermal failures are driven by
temperature and cooling conditions, and mechanical failures by load, wear,
torque and vibration.

The training file \texttt{student\_dataset.csv} has 16,000 rows, and the
test file has 4,000 rows. The columns are unit\_type (S/M/H) and ten
sensors: ambient\_temp, process\_temp, coolant\_flow, shaft\_speed,
drive\_torque, power\_load, component\_wear, thermal\_stress,
mechanical\_load and vibration\_index. The column unit\_id identifies the
machine (16,000 unique values, none of them in the test set) and is never
used as a feature. The evaluation metric is accuracy.

We have used the following models: logistic regression (linear and
quadratic basis), LDA, QDA, Gaussian naive Bayes, decision trees, and
random forests.

\section{Data loading}
% ===========================================================================

We load the three CSV files (training, test and the sample submission)

\section{Exploratory data analysis}

\subsection{Class distribution}

For EDA, the first thing we check is the class balance, since an uneven
split can make accuracy look better than the model actually is. A count
block and a bar plot show the classes are 8,000 / 4,000 / 4,000, that is a
2:1:1 split. A model that always predicts ``normal'' would already score
50\% accuracy, so we report balanced accuracy and per-class metrics
alongside accuracy.

\subsection{Sensor analysis by class}

Next we look at how the sensors behave for each class, since the failures
are supposed to follow the physics. The code computes the per-class sensor
means and draws the mean bars and boxplots (Figures~\ref{fig:machsensors}
and~\ref{fig:machbox}). Accordingly, we observe the following:

\begin{itemize}
  \item Thermal failures (class 1) are hotter: mean process\_temp 72.4
        against 54.7 for normal and 62.2 for mechanical, and mean
        thermal\_stress 37.9 against 21.3 for normal.
  \item Mechanical failures (class 2) show more wear and load: mean
        component\_wear 165.0 against 87.4 for normal, mechanical\_load
        88.0 against 64.8, and vibration\_index 2.10 against 1.51.
  \item Normal machines (class 0) have the lowest values of these
        variables, and the boxes for the two failure classes overlap the
        least exactly where the physical readings differ the most.
\end{itemize}

\subsection{Missing value analysis}

We then check how many values are missing in each column, in order to
decide how to fill them. Missing values are few everywhere: the worst is
vibration\_index, which loses 0.46\% of its values (74 rows), and the
others fall between 0.14\% and 0.38\%. With numbers this small, filling
the gaps with the column median is safe and no rows need to be dropped.
unit\_type has 22 missing entries (0.14\%), which are filled with the most
common type.

\subsection{Correlation analysis}

Next we check the correlations between the sensors, because they decide
whether models that assume independent features are suitable. The heatmap
block prints the strongest pairs as well. Fifteen pairs correlate above
0.5: the strongest are power\_load with thermal\_stress (0.93),
drive\_torque with power\_load (0.92), and process\_temp with
thermal\_stress (0.86). The sensors are therefore far from independent,
which matters for the naive Bayes classifier later.

\subsection{Machine type analysis}

Finally we check the machine type, since failure rates may depend on it.
The type is informative: 42.4\% of H machines are thermal failures, while
S machines lean towards mechanical failures (29.4\%), so we keep the type
as a one-hot feature.

\section{Data cleaning}
% ===========================================================================

There are no impossible values and no duplicate rows, so no rows are
removed. The missing sensor readings are handled by the imputer, and
unit\_id is set aside to line up the submissions.

% ===========================================================================
\section{Feature engineering}
% ===========================================================================

Since the EDA showed that the two failure classes differ mainly in
temperature and in wear and load, we add two kinds of extra features with
one function applied to train and test:

\begin{enumerate}
  \item \texttt{temp\_difference} $=$ process\_temp $-$ ambient\_temp.
        Thermal failures are driven by the machine being hotter than its
        surroundings, and the difference expresses exactly that. It is a
        linear combination of two existing sensors, which is fine for trees
        and logistic regression but matters for QDA
        (Section~\ref{sec:tuning}).
  \item \texttt{power\_per\_speed} $=$ power\_load $/$ shaft\_speed, and
        \texttt{torque\_per\_wear} $=$ drive\_torque $/$ component\_wear:
        rough stress-per-revolution and stress-per-wear ratios that match
        the mechanical failure readings. Division by zero is left as a
        missing value and handled by the imputer.
\end{enumerate}

% ===========================================================================
\section{Data preprocessing}
% ===========================================================================

All preprocessing is built with a scikit-learn \texttt{ColumnTransformer}
and used inside a \texttt{Pipeline}, so during cross-validation the
transformations are fitted on the training folds only.

\begin{itemize}
  \item Missing values: the median for numeric columns, the most frequent
        value for unit\_type.
  \item Encoding: unit\_type is one-hot encoded, with
        \texttt{handle\_unknown="ignore"} in case the test set contains a
        type that training did not see.
  \item Scaling: standardisation for the models that need it (logistic
        regression, LDA, QDA, naive Bayes); the decision tree and the random forest use the raw
        values.
\end{itemize}

% ===========================================================================
\section{Model evaluation}
% ===========================================================================

We report accuracy, balanced accuracy and macro $F_1$. For a two-class
problem with predictions $\hat{y}$ and labels $y$,
\[
  \mathrm{precision} = \frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}}, \qquad
  \mathrm{recall} = \frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}}, \qquad
  F_1 = \frac{2\,\mathrm{precision}\,\mathrm{recall}}
            {\mathrm{precision}+\mathrm{recall}},
\]
and the multi-class versions average these per-class values (macro $F_1$).
Balanced accuracy is the average of the per-class recalls, so it treats
the three classes as equally important even when the split is 2:1:1. The
ROC curve plots
\[
  \mathrm{TPR} = \frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}} \quad\text{against}\quad
  \mathrm{FPR} = \frac{\mathrm{FP}}{\mathrm{FP}+\mathrm{TN}},
\]
and the area under it (AUC) summarises the ranking quality across all
thresholds. All metrics come from code blocks that call
\texttt{sklearn.metrics} on out-of-fold predictions.

For validation we split the training data into $K=5$ stratified folds, so
every fold keeps the class proportions, and average the five scores:
$\frac{1}{K}\sum_{k=1}^{K} e_k$. The finalists are re-checked with 5 folds
repeated 3 times (15 scores each). A fixed random state (42) is used for
every fold split and every model, so the results repeat.

% ===========================================================================
\section{Model family direct comparisons (baseline)}
% ===========================================================================

We first train each classifier from the notes once with reasonable
settings:

\begin{itemize}
  \item \textbf{Bayes rule}: the posterior follows from the prior and the
        likelihood,
        \[
          p(y\mid x) = \frac{p(x\mid y)\,p(y)}{p(x)}.
        \]
        The Bayes optimal classifier predicts the most probable class,
        \[
          f^*(x) = \arg\max_y \, p(y)\,p(x\mid y).
        \]
  \item \textbf{LDA}: Gaussian class-conditional densities with a shared
        covariance matrix, giving linear boundaries.
  \item \textbf{QDA}: Gaussian class-conditional densities with a
        covariance per class, giving quadratic boundaries.
  \item \textbf{Gaussian naive Bayes}: independent Gaussian features per
        class, $p(x\mid y) = \prod_{j=1}^{d} p(x_j\mid y)$.
  \item \textbf{Logistic regression}: models the posterior directly,
        $\eta(x) = \sigma(w^\top x) = 1/(1+e^{-w^\top x})$, fitted by
        maximum likelihood.
  \item \textbf{Decision tree}: recursive binary splitting with the Gini
        impurity, $\mathrm{Gini}(S) = 1 - \sum_k p_k^2$.
  \item \textbf{Random forest}: an average vote over many decorrelated
        trees.
\end{itemize}

The code blocks build these six pipelines, evaluate them with stratified
5-fold cross-validation and draw the comparison chart
(Figure~\ref{fig:machinecomp}).

\begin{center}
\small
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{6.4cm}r@{}}

The random forest leads at 0.878, and QDA is the strongest of the three Gaussian

boundaries are linear, and Gaussian naive Bayes is last at 0.747 because it

\section{Hyper-parameter tuning}\label{sec:tuning}
% ===========================================================================

\subsection{Logistic regression (linear): regularisation strength}

We start with the linear logistic model,
\[
  \eta(x) = P(Y=1\mid X=x) = \sigma(w^\top x)
          = \frac{1}{1+e^{-w^\top x}},
  \qquad \ln\frac{\eta}{1-\eta} = w^\top x,
\]
fitted by minimising the negative log-likelihood
$\mathcal{L}(w) = \sum_n \ln\!\bigl(1+e^{-y_n w^\top x_n}\bigr)$, whose
gradient is $\partial\mathcal{L}/\partial w = \sum_n (\sigma_n - y_n)x_n$.
There is no closed form, so the solver iterates. The strength is set
through \texttt{C}, the inverse of the L2 penalty, and we sweep it. The
results are: $C=0.01$ gives 0.818, $C=0.1$ gives 0.825, $C=1$ gives 0.828,
$C=10$ gives 0.829 and $C=100$ gives 0.829. Accuracy rises up to $C=10$
and stays flat, so the data supports a weak penalty.

\subsection{Logistic regression with a quadratic basis}

Since the boundaries in this dataset are not linear, we give the linear
model squared and interaction terms of the sensors. This lets the linear
decision function bend into a quadratic boundary, the same hypothesis
family as QDA but fitted discriminatively; the code builds a pipeline with
\texttt{PolynomialFeatures(degree=2)} before the logistic model. We try
degree 1 versus 2 and $C \in \{0.01,0.1,1,10\}$. Degree 2 with $C=1$
reaches 0.8853, clearly above the linear version (0.829), and the degree-1
rows repeat the previous sweep as a control.

\subsection{QDA: covariance regularisation}

QDA estimates one covariance matrix per class:
\[
  p(x\mid y) = \frac{1}{(2\pi)^{d/2}|\Sigma_y|^{1/2}}
  \exp\!\Bigl(-\tfrac12 (x-\mu_y)^\top \Sigma_y^{-1} (x-\mu_y)\Bigr),
\]
and the Bayes rule classifies by
$\arg\max_y \bigl[\ln p(y) - \tfrac12\ln|\Sigma_y|
- \tfrac12(x-\mu_y)^\top\Sigma_y^{-1}(x-\mu_y)\bigr]$, a quadratic
boundary. A small regularisation is added to each covariance for numerical
stability. The code block first shows what happens without it: with
\texttt{reg\_param} $=0$ the fit crashes because \texttt{temp\_difference}
is an exact linear combination of two sensors and the class covariance is
singular. With regularisation the best QDA on the engineered features
reaches only 0.8393, below the 0.8476 obtained from the raw sensors at
\texttt{reg\_param} $=0.1$: the redundant column dilutes the covariance
estimate even when the matrix stays invertible. We therefore use the
raw-sensor version as the QDA representative in the final tables.

\subsection{Gaussian naive Bayes: variance smoothing}

The classifier assumes the sensors are conditionally independent given the
class and adds a small smoothing value to every variance. We sweep the
smoothing value from $10^{-9}$ to $0.1$. The best setting (0.1) increases
the score from 0.747 to 0.754. Naive Bayes stays the weakest family by a
wide margin, since the independence assumption does not hold for these
sensors.

\subsection{Decision tree: pre-pruning and cost-complexity pruning}

For pre-pruning we use a grid block over the same four growth limits as the
regression tree (depth, leaf size, split size, maximum leaves). The best
pre-pruned tree combines depth 12 with a minimum leaf size of 5 and scores
0.8389. The unrestricted tree falls to 0.806, and depth-4 trees underfit
around 0.772. For post-pruning we use the cost-complexity criterion
\[
  R_\lambda(T) = R(T) + \lambda |T|,
\]
with candidate $\lambda$ values from the pruning path. Here it helps: the
best $\lambda$ (about $3\times10^{-4}$, keeping 161 leaves) lifts the tree
from 0.8389 to 0.8429 (Figure~\ref{fig:machprune}), while larger $\lambda$
values remove useful branches.

\begin{figure}[H]
\centering
\includegraphics[width=0.56\linewidth]{machine_tree_pruning.png}
\caption{Cost-complexity pruning curve for the classification tree.}
\label{fig:machprune}
\end{figure}

\subsection{Random forest}

The grid tunes the per-tree depth, the minimum leaf size and the class
weighting. We include class weights because the classes are split 2:1:1.
The unweighted depth-14 random forest is the best at 0.8787, but the differences
inside the unweighted block are tiny (0.876 to 0.879). Every
\texttt{balanced} variant scores lower than the matching unweighted run,
the first hint that reweighting trades overall correctness for
minority-class attention.

\section{Experiment: class imbalance handling}
% ===========================================================================

Since the 2:1:1 split could in principle hurt the two failure classes even
while accuracy looks fine, we compare three standard treatments on the two
leading models (the quadratic logistic regression and QDA): reweighting the
classes, random oversampling of the minority classes, and SMOTE, which
creates synthetic minority samples by interpolating between neighbours. The
samplers sit inside imbalanced-learn pipelines after preprocessing, so they
only ever see training folds. We record both accuracy and macro $F_1$,
since accuracy alone could hide a poor minority class.

\begin{table}[H]
\centering
\caption{Imbalance strategies for the quadratic logistic (5-fold CV).}
\label{tab:imbalance}
\small
\begin{tabular}{@{}lrr@{}}
\toprule
Variant & Accuracy & Macro $F_1$ \\
\midrule
none & 0.8853 & 0.8756 \\
reweight (class weights) & 0.8743 & 0.8666 \\
random oversampling & 0.8728 & 0.8649 \\
SMOTE & 0.8734 & 0.8660 \\
\bottomrule
\end{tabular}

Each of these experiment scenarios lowered both metrics. With classes that
are already well separated and only a 2:1:1 split, the resampled training
set biases the boundary towards synthetic or duplicated minority points
without improving any real case, so we keep the unweighted models.

\section{Conclusion}
% ===========================================================================

\begin{itemize}
  \item The classes are split 2:1:1, but the per-class and balanced metrics
        show that accuracy is not hiding a weak class: the weakest recall
        is 83.3\% on thermal failures, and the leading model is best on
        accuracy, balanced accuracy and macro $F_1$ at the same time.
  \item The sensors separate the classes in the way the failure physics
        suggests, and the engineered temperature difference and load ratios
        sharpen that separation.
  \item Quadratic boundaries matter: giving logistic regression a degree-2
        basis takes it from 0.829 to 0.8853, ahead of QDA (0.848) and the random forest (0.879). The random forest is a close second.
  \item Tree tuning confirmed both pruning routes: pre-pruning peaks at
        depth 12 with leaf size 5 (0.839), and cost-complexity post-pruning
        with $\lambda$ about $3\times10^{-4}$ improves it to 0.8429 with
        161 leaves. All tree variants stay behind the top two models.
  \item Reweighting, oversampling and SMOTE all reduced both accuracy and
        macro $F_1$, so the final models are unweighted.
  \item The best model is the quadratic-basis logistic regression
        (0.8853 $\pm$ 0.0056), and its submission scores 0.88812 on the
        public leaderboard.
  \item We also test the model on an 80/20 split of the training data: it
        scores 0.8953 when we train it on 80\% of the rows, and still 0.8872
        after cutting the training set down to 20\%, so the decision
        boundary is stable and does not lean on data volume.
\end{itemize}
